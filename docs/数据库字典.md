# 校园美食地图数据库字典

本文档记录第一阶段全部数据表、字段、类型、约束、默认值与业务含义，与《技术路线与开发说明》第六章保持一致。

SQLite 不支持 PostgreSQL 那样的原生表注释机制，因此中文说明保存在三个位置：SQLAlchemy 模型的 `comment` 属性、Alembic 迁移脚本的中文说明、以及本文档。

## 通用约定

- 所有字段名使用英文 `snake_case`，表名使用英文小写复数。
- 时间字段统一以 UTC 保存，接口返回时使用 ISO 8601 格式。
- 主键使用整数自增 `id`；校园使用稳定的字符串主键 `campus_id`。
- 枚举取值：
  - `campuses.map_type`：`image`（图片底图）、`real`（真实地图）。
  - `users.role`：`user`（普通用户）、`admin`（管理员）。
  - `shops.shop_type`：`shop`（商铺）、`vendor`（摊贩）。
  - `shops.status`：`pending`（待审核）、`approved`（已通过）、`rejected`（已拒绝）。
  - `reviews.status`、`review_replies.status`：`visible`（可见）、`hidden`（已隐藏）。
  - `review_reactions.reaction_type`：`like`（点赞）、`dislike`（点踩）。
  - `reports.status`：`pending`（待处理）、`resolved`（已处理）、`dismissed`（已驳回）。
- 删除策略（通过外键 `ON DELETE` 实现）：
  - 校园 → 店铺：`RESTRICT`，不允许误删仍有店铺的校园。
  - 用户 → 店铺/评价/互动/回复/举报：`RESTRICT`，用户不参与级联删除。
  - 店铺 → 评价：`CASCADE`；评价 → 互动、回复、举报：`CASCADE`，避免产生孤立记录。
  - 店铺/举报的审核人与处理人：`SET NULL`，保留业务记录本身。
- 表清单：

| 表名 | 中文名 |
| --- | --- |
| `campuses` | 校园及其地图配置表 |
| `users` | 系统用户表 |
| `shops` | 校园美食店铺表 |
| `reviews` | 用户店铺评价表 |
| `review_reactions` | 评价点赞与点踩表 |
| `review_replies` | 评价回复表 |
| `reports` | 评价举报及处理记录表 |

## 一、`campuses`：校园及其地图配置表

用途：管理校园基本信息、底图类型、默认视图与校外范围配置；校园通过配置文件与初始化脚本维护，业务代码不写死具体学校。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `campus_id` | VARCHAR(50) | 是 | 无 | 校园唯一标识（主键，稳定字符串，如 `swjtu_xipu`） |
| `campus_name` | VARCHAR(100) | 是 | 无 | 校园名称 |
| `map_type` | VARCHAR(10) | 是 | `image` | 地图类型：`image` 或 `real` |
| `map_asset_url` | VARCHAR(500) | 否 | 空 | 图片底图资源路径；图片模式必填 |
| `tile_url_template` | VARCHAR(500) | 否 | 空 | 真实地图瓦片地址模板；真实地图模式必填 |
| `map_attribution` | VARCHAR(300) | 否 | 空 | 地图署名文本；真实地图模式必填 |
| `allow_off_campus` | BOOLEAN | 是 | `false` | 是否允许展示校园范围以外的店铺 |
| `image_width` | INTEGER | 否 | 空 | 图片底图宽度（像素）；图片模式必填 |
| `image_height` | INTEGER | 否 | 空 | 图片底图高度（像素）；图片模式必填 |
| `default_map_x` | FLOAT | 否 | 空 | 图片底图默认中心横向比例（0 至 1）；图片模式必填 |
| `default_map_y` | FLOAT | 否 | 空 | 图片底图默认中心纵向比例（0 至 1）；图片模式必填 |
| `default_latitude` | FLOAT | 否 | 空 | 真实地图默认中心纬度（-90 至 90）；真实地图模式必填 |
| `default_longitude` | FLOAT | 否 | 空 | 真实地图默认中心经度（-180 至 180）；真实地图模式必填 |
| `default_zoom` | FLOAT | 是 | `1` | 默认缩放级别，必须大于 0 |
| `boundary_radius_meters` | FLOAT | 否 | 空 | 真实地图校园范围半径（米），必须大于 0；为空时后端不做范围过滤 |
| `is_active` | BOOLEAN | 是 | `true` | 是否允许正常访问 |
| `created_at` | DATETIME | 是 | 当前 UTC 时间 | 创建时间（UTC） |
| `updated_at` | DATETIME | 是 | 当前 UTC 时间 | 更新时间（UTC） |

约束与校验：

1. `map_type IN ('image', 'real')`。
2. 图片模式必须同时提供底图路径、宽高与中心点。
3. 真实地图模式必须同时提供瓦片模板、署名与经纬度中心。
4. 比例坐标范围 0 至 1，纬度范围 -90 至 90，经度范围 -180 至 180。
5. 删除校园前必须检查关联数据（`RESTRICT`），不允许级联删除全部店铺与评价。
6. 真实地图模式可以通过 `boundary_radius_meters` 定义校园范围；后端公开点位查询会按该半径过滤，不能只依赖前端视野。

## 二、`users`：系统用户表

用途：保存用户名、密码哈希与角色；不设置头像、邮箱或手机号字段。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | INTEGER | 是 | 自增 | 用户主键 |
| `username` | VARCHAR(20) | 是 | 无 | 用户名，唯一，长度 2 至 20 个字符 |
| `password_hash` | VARCHAR(255) | 是 | 无 | 密码哈希（Argon2id），不保存明文密码 |
| `role` | VARCHAR(10) | 是 | `user` | 用户角色：`user` 或 `admin` |
| `is_active` | BOOLEAN | 是 | `true` | 账号是否启用 |
| `created_at` | DATETIME | 是 | 当前 UTC 时间 | 创建时间（UTC） |
| `updated_at` | DATETIME | 是 | 当前 UTC 时间 | 更新时间（UTC） |

约束与校验：

1. `username` 唯一约束 `uq_users_username`。
2. `role IN ('user', 'admin')`；普通用户注册接口不允许指定 `admin`。
3. 管理员只能通过初始化脚本或受控管理命令创建。

## 三、`shops`：校园美食店铺表

用途：保存商铺与摊贩信息、审核状态与地图坐标。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | INTEGER | 是 | 自增 | 店铺主键 |
| `campus_id` | VARCHAR(50) | 是 | 无 | 所属校园（外键 `campuses.campus_id`，`RESTRICT`） |
| `name` | VARCHAR(100) | 是 | 无 | 店铺名称（必填，不能为空串） |
| `description` | TEXT | 是 | 无 | 店铺简介（必填，不能为空串） |
| `shop_type` | VARCHAR(10) | 是 | 无 | 店铺类型：`shop` 或 `vendor` |
| `photo_url` | VARCHAR(500) | 否 | 空 | 封面照片路径，可为空 |
| `submitted_by` | INTEGER | 是 | 无 | 提交用户（外键 `users.id`，`RESTRICT`） |
| `status` | VARCHAR(10) | 是 | `pending` | 审核状态：`pending`、`approved` 或 `rejected` |
| `map_x` | FLOAT | 否 | 空 | 图片模式横向比例坐标（0 至 1） |
| `map_y` | FLOAT | 否 | 空 | 图片模式纵向比例坐标（0 至 1） |
| `latitude` | FLOAT | 否 | 空 | 真实地图纬度（-90 至 90） |
| `longitude` | FLOAT | 否 | 空 | 真实地图经度（-180 至 180） |
| `reviewed_by` | INTEGER | 否 | 空 | 审核管理员（外键 `users.id`，`SET NULL`） |
| `reviewed_at` | DATETIME | 否 | 空 | 审核时间（UTC） |
| `rejection_reason` | VARCHAR(500) | 否 | 空 | 拒绝原因；状态为 `rejected` 时必填 |
| `created_at` | DATETIME | 是 | 当前 UTC 时间 | 创建时间（UTC） |
| `updated_at` | DATETIME | 是 | 当前 UTC 时间 | 更新时间（UTC） |

约束与校验：

1. 店铺类型只允许 `shop`、`vendor`；状态只允许 `pending`、`approved`、`rejected`。
2. 图片模式坐标（`map_x`、`map_y`）必须成对出现且范围 0 至 1；经纬度必须成对出现且范围合法。
3. 每家店铺至少要有一组坐标（`map_x` 或 `latitude`）。
4. 坐标体系必须与所属校园的 `map_type` 一致，该跨表规则由业务层校验。
5. 新店铺状态固定为 `pending`，普通用户不能自行提交 `approved`。
6. 被拒绝的店铺必须填写拒绝原因。

索引：`ix_shops_campus_id_status`（校园 + 状态，用于公开点位查询）、`ix_shops_submitted_by`（个人提交记录与贡献统计）。

## 四、`reviews`：用户店铺评价表

用途：保存用户对店铺的 1 至 5 星评分与文字评价；每条评价是评分统计的样本。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | INTEGER | 是 | 自增 | 评价主键 |
| `shop_id` | INTEGER | 是 | 无 | 被评价店铺（外键 `shops.id`，`CASCADE`） |
| `user_id` | INTEGER | 是 | 无 | 评价用户（外键 `users.id`，`RESTRICT`） |
| `rating` | INTEGER | 是 | 无 | 评分，1 至 5 的整数 |
| `content` | TEXT | 是 | 无 | 文字评价，1 至 2000 个字符 |
| `status` | VARCHAR(10) | 是 | `visible` | 评价状态：`visible` 或 `hidden` |
| `created_at` | DATETIME | 是 | 当前 UTC 时间 | 创建时间（UTC） |
| `updated_at` | DATETIME | 是 | 当前 UTC 时间 | 更新时间（UTC） |

约束与校验：

1. 唯一约束 `uq_reviews_shop_id_user_id`：每名用户对同一家店铺最多保留一条主评价。
2. `rating BETWEEN 1 AND 5`；`content` 长度 1 至 2000。
3. 隐藏评价（`hidden`）不参与评分与排行榜统计。
4. 回复不计入店铺评分样本。
5. 删除评价时，其互动、回复与举报记录级联删除，不留孤立数据。

索引：`ix_reviews_shop_id_status`（店铺评价列表与评分统计）。

## 五、`review_reactions`：评价点赞与点踩表

用途：记录用户对评价的点赞或点踩。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | INTEGER | 是 | 自增 | 互动主键 |
| `review_id` | INTEGER | 是 | 无 | 目标评价（外键 `reviews.id`，`CASCADE`） |
| `user_id` | INTEGER | 是 | 无 | 互动用户（外键 `users.id`，`RESTRICT`） |
| `reaction_type` | VARCHAR(10) | 是 | 无 | `like` 或 `dislike` |
| `created_at` | DATETIME | 是 | 当前 UTC 时间 | 创建时间（UTC） |
| `updated_at` | DATETIME | 是 | 当前 UTC 时间 | 更新时间（UTC） |

约束与校验：

1. 唯一约束 `uq_review_reactions_review_id_user_id`：同一用户对同一条评价只能存在一种互动。
2. 重复点击同一种互动时取消互动；点击另一种互动时切换类型（由业务层实现）。
3. 统计点赞数与点踩数时只计算有效记录。

索引：`ix_review_reactions_user_id`。

## 六、`review_replies`：评价回复表

用途：保存对评价的一级回复，不支持回复再回复。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | INTEGER | 是 | 自增 | 回复主键 |
| `review_id` | INTEGER | 是 | 无 | 所属主评价（外键 `reviews.id`，`CASCADE`） |
| `user_id` | INTEGER | 是 | 无 | 回复者（外键 `users.id`，`RESTRICT`） |
| `content` | TEXT | 是 | 无 | 回复文本，1 至 1000 个字符 |
| `status` | VARCHAR(10) | 是 | `visible` | 回复状态：`visible` 或 `hidden` |
| `created_at` | DATETIME | 是 | 当前 UTC 时间 | 创建时间（UTC） |
| `updated_at` | DATETIME | 是 | 当前 UTC 时间 | 更新时间（UTC） |

约束与校验：

1. `content` 长度 1 至 1000，不能为空。
2. 只支持一级回复；回复数量不计入店铺评分样本。
3. 管理员处理违规内容时可以隐藏回复。

索引：`ix_review_replies_review_id_status`。

## 七、`reports`：评价举报及处理记录表

用途：记录举报内容与管理员处理结果，处理过程可追溯。

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | INTEGER | 是 | 自增 | 举报主键 |
| `review_id` | INTEGER | 是 | 无 | 被举报评价（外键 `reviews.id`，`CASCADE`） |
| `reported_by` | INTEGER | 是 | 无 | 举报用户（外键 `users.id`，`RESTRICT`） |
| `reason` | TEXT | 是 | 无 | 举报理由，不能为空 |
| `status` | VARCHAR(10) | 是 | `pending` | 处理状态：`pending`、`resolved` 或 `dismissed` |
| `handled_by` | INTEGER | 否 | 空 | 处理管理员（外键 `users.id`，`SET NULL`） |
| `handled_at` | DATETIME | 否 | 空 | 处理时间（UTC） |
| `handling_note` | TEXT | 否 | 空 | 处理备注 |
| `created_at` | DATETIME | 是 | 当前 UTC 时间 | 举报时间（UTC） |

约束与校验：

1. 唯一索引 `uq_reports_pending_review_id_reported_by`（部分索引，仅约束 `status = 'pending'`）：同一用户不能对同一条评价重复提交待处理举报。
2. 举报不会自动隐藏评价；管理员可以驳回举报或隐藏评价。
3. 处理记录必须保存处理人、处理时间与备注。

索引：`ix_reports_status`、`uq_reports_pending_review_id_reported_by`（部分唯一索引）。

## 八、管理员初始化说明

1. 首次初始化：`python -m app.db.init_db`，管理员账号为 `admin`。
   - 优先使用命令行参数 `--admin-password` 或环境变量 `ADMIN_INITIAL_PASSWORD`；
   - 两者都没有时自动生成随机密码并打印一次，不会使用演示密码。
2. 单独创建或维护管理员：`python -m app.db.create_admin --username 平台管理员`。
   - 已存在的普通用户需要显式使用 `--promote-existing` 才能提升为管理员；
   - 已存在的管理员需要显式使用 `--reset-password` 才能重置密码。
3. 演示普通用户（如“美食探索者”）统一使用演示密码 `demo-password-2026`，仅供本地开发与界面测试，正式部署前必须替换或停用。
